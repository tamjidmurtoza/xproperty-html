Xproperty Documentation

Thank you for choosing Xproperty, a real estate and property listing HTML template built with Bootstrap 5, SCSS and jQuery. This guide covers setup, customisation and every component the template ships with.

Requirements

Xproperty is plain HTML, CSS and JavaScript, so there are no server requirements. You only need:

  • A code editor, such as VS Code.
  • A modern web browser to preview pages.
  • Optional: Dart Sass (or Node.js) if you want to edit the SCSS source.
  • Any web hosting that serves static files to go live.

Installation

  1. Unzip the package you downloaded.
  2. Open index.html (or any other page) in your browser to preview it.
  3. Edit the HTML in your code editor. Styles live in assets/css/style.css and scripts in assets/js/main.js.
  4. Replace the demo text and images with your own content.

Use a local server such as the VS Code Live Server extension while you edit. The page reloads automatically on save, and embedded maps and videos behave the same as they will online.

Deployment

Upload the contents of the template folder (all .html files and the assets folder) to your hosting's public directory, usually public_html or www. Keep the folder structure unchanged so relative paths keep working.

You can also deploy for free on static hosts such as Netlify, Vercel, GitHub Pages or Cloudflare Pages by dragging in the folder or connecting a Git repository.

Before going live, add your own Web3Forms access key to the contact form (see Contact Form), replace example.com with your domain (see SEO & Accessibility) and remove pages you don't use from the navigation menu.

Dashboard pages use <body class="cs_dashboard">, which turns on the dashboard-only scripts in main.js:

  • Sidebar: collapses to icons on desktop (the choice is remembered) and becomes an off-canvas menu on mobile. Add a nested <ul> to a menu item for a submenu. Menu items are grouped under headings: the owner sidebar has a Rentals group (Tenants & Leases, Rental Applications, Maintenance) and the admin sidebar a Communication group (Messages, Support Tickets).
  • Topbar: notification and profile dropdowns, mobile search and a color mode button.
  • Overview widgets: animated stat counters and SVG analytics charts (mirrored in RTL: time runs right to left and the value axis moves to the right).
  • Filter tabs: filter listings, approvals, users, leads and tours by status.
  • Row actions: a button with data-set-status="confirmed", data-status-label and data-status-class changes its row's status badge and refreshes the tab counts (mark lead as contacted, accept / decline tours, approve / reject properties, verify / suspend agents, cancel a tour). It works for table rows and card lists, and a <form data-set-status> in a dashboard modal updates the row that opened it (e.g. sending a counter offer).
  • Offers & rentals: offers pages (agent, owner, buyer) accept, counter, decline or withdraw offers; the owner manages tenants & leases, rental applications (screen / approve / decline) and maintenance requests; buyers track their offers and rental applications.
  • Documents: agent and owner documents.html list contracts and files with uploads. Upload previews show an image thumbnail, or a file chip for PDF / DOCX files.
  • Admin tools: listing settings (property types, amenities, locations), blog posts with a post editor, coupons, a roles & permissions matrix (see ROLE_PRESETS in main.js), messages and support tickets with a reply thread (replies can be internal notes; Reply & Close resolves the ticket).
  • Wide tables: from 1200px a table that is wider than its card gets a thin horizontal scrollbar; narrower tables keep their tooltips and action menus unclipped.
  • Table search & export: <form data-table-search="#tableId"> filters rows as you type; <button data-export-table="#tableId" data-export-name="leads.csv"> downloads the visible rows as CSV.
  • Tour calendar: <div data-tour-calendar data-month="2026-10" data-target="#tourTable"> draws a month view, marks days that have rows with data-tour-date="YYYY-MM-DD" and highlights a day's tours on click.
  • Saved properties: buyer/saved-properties.html lists the homes visitors save with the heart button (search, sort, type filter and remove work).
  • Invoices: invoice.html prints as a clean A4 page or PDF with the Print button.
  • Notifications: notifications.html lists every notification with All / Unread / Read filters, mark as read and delete. The topbar dropdown links to it.
  • Messages: a chat layout with a conversation list and message thread.
  • Forms: image upload previews on the submit and edit property pages, and a package editor on admin/edit-package.html.

The dashboards are front-end only. Connect the forms, tables and messages to your own backend.

HTML Structure

Every page follows the same skeleton: preloader, header, page sections and footer. CSS loads in the <head> and scripts load just before </body>.

<body>
  <div class="cs_preloader">…</div>                     <!-- Preloader -->
  <header class="cs_site_header cs_sticky_header …">…</header>

  <section>…</section>                                   <!-- Page sections -->

  <footer class="cs_footer …">…</footer>

  <script src="assets/js/jquery.min.js"></script>
  <!-- plugin scripts … -->
  <script src="assets/js/main.js"></script>
</body>

Sections are self-contained. You can copy a section from one page to another as long as the target page loads the same plugin files.

Preloader

The preloader fades out once the page has loaded. To remove it, delete the cs_preloader block from the page.

Logo & Favicon

The logo is an <img> inside .cs_site_brand in the header (and again in the footer). Replace the file or point the src to your own logo:

<a href="index.html" class="cs_site_brand">
  <img src="assets/img/logo.svg" alt="Your Company">
</a>

Replace assets/img/favicon.png with your own icon (a square PNG, 32×32 or larger) to update the browser-tab icon on every page.

Fonts

The template uses Cabin for headings, Raleway for body text and Carattere for decorative script text. They're loaded from Google Fonts with an @import at the top of style.css (_typhography.scss in SCSS).

  1. Pick your fonts on Google Fonts and copy the embed URL.
  2. Replace the @import url(…) line at the top of style.css.
  3. Update the font variables:
:root {
  --primary-font: "Cabin", sans-serif;      /* headings */
  --secondary-font: "Raleway", sans-serif;  /* body text */
  --ternary-font: "Carattere", cursive;     /* decorative */
}

Dark Mode

Every page has three color modes: Device (follows the visitor's system setting), Light and Dark. The default is Device.

  • Template pages: a gear button opens a settings panel with Device / Light / Dark buttons (below the LTR / RTL buttons).
  • Dashboard pages: the topbar button cycles Device → Light → Dark.

The choice is saved in localStorage (xproperty-theme) and applied on every page. Dark mode works by adding the cs_dark class to <html>, which redefines the color variables, so every component follows automatically.

To force a page to stay dark whatever the visitor picks, add the class yourself:

<body class="cs_dark">

Edit the dark palette in the .cs_dark { … } block of _variable.scss (or style.css). The default mode and the button order are set by THEME_MODES near the top of main.js.

RTL Layout

Every page supports right-to-left languages such as Arabic and Hebrew. In RTL mode the layout is mirrored, Bootstrap's RTL build (bootstrap.rtl.min.css) is loaded in place of the regular one, and the Cairo font is added for Arabic text. Sliders, selects and icons flip direction too.

The direction is picked in this order:

  1. A ?dir=rtl or ?dir=ltr parameter in the URL, e.g. index.html?dir=rtl.
  2. The visitor's last choice from the LTR / RTL buttons, saved in localStorage (xproperty-dir).
  3. The dir attribute in the page markup.

To make a page RTL by default, set the attribute on <html>:

<html lang="ar" dir="rtl">

On template pages the LTR / RTL buttons are in the gear settings panel. On dashboard pages they are always visible. RTL style overrides live in assets/sass/default/_rtl.scss. A page whose <html lang> is ar, he, fa or ur is always laid out RTL, whatever the saved choice. The dashboard analytics and property price history charts mirror too.

Numbers in RTL text

In RTL mode, English text that starts with a number or symbol can be reordered by the browser (for example $3,200/mo or 3 Beds). The template wraps such text in <bdi> so it keeps its own direction: prices, phone numbers, invoice IDs, addresses and spec labels. Do the same in your own content:

<p>Est. Payment <bdi>$3154/mo</bdi></p>
<h2><bdi>3 Beds</bdi></h2>
<a href="tel:+12144466668"><bdi>(214) 446-6668</bdi></a>

To remove the gear button and settings panel (and the LTR / RTL buttons on dashboard pages), delete settingsSwitch(); from the init list in main.js. Pages then use the direction in their markup or URL.

SCSS

SCSS is optional. assets/sass/style.scss imports every partial in this order: variables, typography, spacing, general, header, footer, sidebar, slider, video modal, preloader, then the component partials and the dark version. Styles for the newer pages are in shortcode/_new-public-a/b/c.scss (public pages), _new-admin-a/b.scss (admin) and _new-dash-a/b.scss (agent, owner and buyer), imported right after the dashboard partial. Compile it to assets/css/style.css with the npm scripts in package.json (run npm install once first):

npm run watch:css   # recompile on every save while you edit
npm run build:css   # one-off build with Autoprefixer vendor prefixes

Without Node.js, any Sass compiler works, such as the VS Code Live Sass Compiler extension or sass assets/sass/style.scss assets/css/style.css --watch.

Compiling overwrites style.css. Pick one workflow: edit either the SCSS or the CSS, not both.

Header & Menu

The header has three areas: cs_main_header_left (logo), cs_main_header_center (navigation) and cs_main_header_right (language, login and call-to-action).

  • Sticky header: keep cs_sticky_header on <header> and it gets cs_sticky_active once the page scrolls. Remove the class to keep the header static.
  • Dropdowns: add menu-item-has-children to an <li> that contains a nested <ul>. On mobile, a toggle arrow is added automatically.
  • Two-column dropdown: add cs_dropdown_2col to a long dropdown list (the Pages menu uses it) to show it in two columns on desktop. On mobile it stays a single list.
  • Listing menu: also links to New Developments, Open House and Neighborhood Guides.
  • Skip link: every page starts with <a href="#main-content" class="cs_skip_link">; keep id="main-content" on the first content element when you build a new page.
  • Mobile menu: the hamburger button is generated by main.js. No extra markup is needed.

Sliders

Sliders use Slick and are configured with data attributes on .cs_slider_container, so no JavaScript changes are needed. Each slider lives inside a .cs_slider wrapper.

<div class="cs_slider">
  <div class="cs_slider_container"
       data-autoplay="0" data-loop="1" data-speed="800"
       data-center="0" data-variable-width="0"
       data-slides-per-view="responsive"
       data-xs-slides="1" data-sm-slides="2" data-md-slides="2"
       data-lg-slides="3" data-add-slides="3">
    <div class="cs_slider_wrapper">
      <div class="cs_slide">…</div>
      <div class="cs_slide">…</div>
    </div>
  </div>
  <div class="cs_left_arrow">…</div>   <!-- optional arrows -->
  <div class="cs_right_arrow">…</div>
  <div class="cs_pagination"></div>     <!-- optional dots -->
</div>

Location search

A Tom Select named property-location becomes a searchable location field: visitors can type a city or a country, each option shows its country, and "No locations found" appears when nothing matches. Countries come from LOCATION_COUNTRIES in main.js. To add a city, add an <option> and its country:

<select class="tom_select" name="property-location">
  <option value="">Search Location...</option>
  <option value="dubai">Dubai</option>
  <option value="lisbon">Lisbon</option>
</select>
var LOCATION_COUNTRIES = {
  dubai: "United Arab Emirates (UAE)",
  lisbon: "Portugal",   // new city
};

Contact Form

Forms with id="cs_form" are sent with AJAX to Web3Forms, a free form backend that needs no server code. The response message appears in #cs_result.

  1. Create a free access key at web3forms.com using the email address that should receive messages.
  2. Paste the key into the hidden access_key input of each form.
  3. Make sure the form contains an element with id="cs_result" for the status message.
<form id="cs_form" class="cs_contact_form">
  <input type="hidden" name="access_key" value="YOUR_WEB3FORMS_ACCESS_KEY">
  <input type="text" name="name" placeholder="Name" required>
  <input type="email" name="email" placeholder="Email" required>
  <textarea name="message" placeholder="Message"></textarea>
  <button type="submit">Send</button>
  <div id="cs_result"></div>
</form>

The form ships with the placeholder YOUR_WEB3FORMS_ACCESS_KEY. Until you replace it, submitting shows a demo success message and nothing is sent.

Spam protection

  • Honeypot (always on): the hidden botcheck checkbox is invisible to people. If a bot ticks it, the form shows a success message but sends nothing. Keep it in every form: <input type="checkbox" name="botcheck" class="d-none" tabindex="-1" aria-hidden="true">
  • hCaptcha (optional): contact.html contains commented hCaptcha markup. Uncomment it and turn on hCaptcha in your Web3Forms dashboard; the form then asks visitors to complete the captcha before sending.

Maps

All maps use Leaflet with OpenStreetMap tiles, so no API key is needed. Pages with a map load assets/css/leaflet.min.css and assets/js/leaflet.min.js.

Location map with a pin

Used on the contact page, property details and several home demos:

<div class="cs_location_map cs_radius_10">
  <div class="cs_leaflet_map" data-map data-lat="40.7484" data-lng="-73.9857" data-zoom="15"
       data-title="Our Office" data-address="350 Fifth Avenue, New York"></div>
</div>

Add data-pin="false" to hide the pin. Find coordinates by right-clicking a place in Google Maps or OpenStreetMap.

Half-map search

property-listing-map.html shows a price marker for every card that has data-lat and data-lng. Markers cluster when zoomed out (Leaflet.markercluster), hovering a card highlights its marker, and Search as I move the map limits the list to the visible area.

OpenStreetMap's free tiles are for light use only. For a busy site, change MAP_TILES in main.js to a provider such as MapTiler, Stadia Maps or Mapbox.

Search & Filters

The listing pages filter, sort and paginate their cards in the browser. Each card carries its data as attributes:

<div class="col-md-6 cs_listing_item">
  <div class="cs_card cs_style_1" data-id="buy-1" data-type="house" data-offer="buy"
       data-location="new-york" data-price="450000" data-beds="3" data-baths="2" data-area="1450"
       data-amenities="garden,parking" data-date="2026-09-28" data-views="812">…</div>
</div>
  • The grid is .cs_listing_grid with data-per-page="6"; the pagination list has data-listing-pagination and the result count data-result-count.
  • Any checkbox or select with data-filter="type" (or beds, baths, location, offer, amenities) filters the cards. value="5+" means five or more; data-filter-mode="min" on a select means "at least".
  • Inputs named min-price, max-price, min-area and max-area set ranges. A .cs_range_slider data-range="price" stays in sync with the price inputs.
  • [data-listing-sort] sorts by newest, popularity or price; .cs_view_btn switches between grid and list view (remembered).
  • The home page search forms open the buy or rent listing with the choices in the URL, for example property-listing-buy.html?type=villa&beds=3&max-price=900000. Set a real action on the form to send searches to your own backend instead.

With a backend, render only the matching cards server-side and keep the same markup: the filters, sort and layout toggle still work on the returned cards.

Compare & Saved Homes

These features are front-end demos only: nothing is stored, and the page resets on reload. Connect them to user accounts in your backend for production.

  • Compare: any <button data-compare-toggle> inside a property element ([data-id]) adds it to a list of up to 4. A floating bar shows the picks and links to compare.html, which renders the side-by-side table from COMPARE_DEMO in main.js.
  • Save: <button data-save-toggle> (and the older .cs_heart_toggler) toggles the saved state. buyer/saved-properties.html shows sample saved homes with search, sort, filter and remove.
  • Share & print: the property details header has share links (and the system share sheet on phones), copy link and a print-friendly brochure layout.
  • Save search: the Save Search button on listing pages opens a panel to name the search and pick an alert frequency; buyer/saved-searches.html shows sample searches with delete.
  • Reviews: property details shows the average, star bars and a Write a Review form; a submitted review is added to the list until reload. The agent and owner Reviews pages support Reply, Report and sorting.
  • Price history: rows in [data-price-table] with data-date and data-price fill the table and draw the chart.

The grid / list view choice is remembered in localStorage (xproperty-listing-view).

Form Validation

Forms with data-auth-form (login, register, forgot password, contact widgets, tour requests) are checked before sending: required, email format, minlength and data-match="password" for the confirm field. Errors show under each field, then the button shows a loading state and a success message.

  • data-redirect="buyer/index.html" opens a page after success; {role} and {email} are replaced with the form's values (register goes to verify-email.html, then to the dashboard for the chosen role).
  • data-success="…" sets a custom success message.
  • With action="#" the form stays on the page (demo). Set a real action and valid forms post to your backend.
  • Password fields get a show / hide button automatically. Newsletter forms check the email and confirm the sign-up.
  • Submit property: <form data-property-form="submit" data-wizard> turns the cards with data-step="1"–"4" into a step-by-step wizard with a generated Review step; each step is validated before moving on. data-property-form="edit" validates the edit forms.
  • Blog: posts carry data-category and data-tags; sidebar categories, tags and search filter the list (or open blog.html?category=… from other pages).

Language Switcher

The header includes a flag dropdown (EN, BN, ES, AR, ZH, DE) built with flag-icon CSS. The switcher works out of the box:

  • The choice is saved in localStorage (xproperty-lang) and its flag is shown on every page.
  • Arabic turns on the RTL layout.
  • Any other language turns RTL off. On a translated page it returns to the original page.
  • A page with <html lang="ar"> (or he, fa, ur) is always RTL.

Translations and RTL languages are set in section 08 (Language Select) of main.js. Add an entry for each page you translate:

var LANGUAGE_PAGES = {
  // AR: { "index.html": "index-ar.html", "about-us.html": "about-us-ar.html" },
  // DE: { "index.html": "index-de.html" },
};
var RTL_LANGUAGES = ["AR"];                 // languages that switch the layout to RTL

To add a language, copy a button in .cs_language_dropdown and change the flag-icon-xx class (two-letter country code) and data-lang value. Languages without a translated page only change the saved choice and the direction, so connect them to your own translations or i18n solution.

Only the six flags in use ship in assets/flags. For another language, download its SVG from flag-icons and add it to both assets/flags/4x3 and assets/flags/1x1.

Animations & Scrolling

Scroll animations (AOS)

Elements animate in when they have a data-aos attribute. See the AOS docs for all effects.

<div data-aos="fade-up" data-aos-delay="100">…</div>

To disable all scroll animations, remove aosInit(); from the init list in main.js and delete the data-aos attributes.

Smooth scrolling (Lenis)

Lenis adds inertial smooth scrolling. To use the browser's native scrolling, remove smoothScroll(); from the init list in main.js.
